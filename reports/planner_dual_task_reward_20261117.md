# 完整球历史 planner 的双任务 task-reward 训练

本轮在完整球历史基线 `0d98300f` 上训练传球、射门两个条件 latent 修正分支，共享原 planner、初始传球修正、球历史处理、射门后恢复和冻结 AH-BFM。两个分支均覆盖接近球至触球前；不是只训练传球后的射门分支，也不是新增一个固定 walk latent。

作者的本地 AH-BFM 包提供 actor/backward encoder，没有命名 walk latent 库。专家接近球的动作可以通过原监督数据和本轮任务奖励进入 planner；这不证明任意行走 latent 与射门 latent 插值就能可靠切换。

任务奖励保留已有射门质量和联合完成项，新增传球接近、方向/速度/规定脚质量、稳定、失败和动作变化项。传球/射门分别归一化优势。新增传球专家 `model_655000.pt` 作为传球动作辅助监督，权重0.1；推理不调用专家。此轮是“双任务奖励 + 新传球专家约束”的组合实验，不能单独归因于其中某一项。

训练场景和评测场景均保留原固定协议：射门物理/动作/重置/事件配置，传球来球命令，触球50步后采样第二个球，射门10步后恢复，20秒时域；不在技能切换时重置机器人或动作历史。这是两次球事件的连续任务，不是真实比赛中同一个球连续传射。

新传球包保存配置引用当前运行环境缺失的奖励函数。兼容函数从包内diff提取供checkpoint反序列化使用；本轮未声称完整复现新包训练代码，采用固定旧场景以保证训练前后可比。新旧保存的观测和动作定义一致。

已完成零初始化等价、两分支梯度和触球事件只奖励一次的离线检查。32环境16轮smoke通过：两分支权重改变，冻结共享参数不变，导出回读一致。两次早期初始化失败记录保留，不计作训练结果。

正式协议：种子819101，128环境，200轮×32步，共819200环境步；探索std0.05，anchor0.000625，PPO学习率4e-5；只选择最终checkpoint。独立评测种子819201/819202，每种子每模型32回合，共64回合/模型，所有失败保留分母，不自动更换默认模型。

正式训练与全部评测已完成。最终训练checkpoint为 `1def3ddec5b70f54c7a527eee6617aaacebdc997dbe3a6b70cff394afcac829a`，1860次actor更新、3200次critic更新。独立检查确认只有两分支共8个参数张量改变；共享checkpoint和归一化缓冲不变。版本化导出通过传球/射门/恢复逐值回读检查，旧加载器会拒绝该格式，避免静默忽略新分支。

## 独立连续评测

| 指标 | 完整球历史基线 | 双任务奖励训练后 |
|---|---:|---:|
| 传球触球 | 63/64 | 63/64 |
| 准确传球 | 24/64 | 23/64 |
| 射门触球 | 39/64 | 33/64 |
| 准确射门 | 10/64 | 7/64 |
| 完整成功 | 3/64 (4.69%) | 2/64 (3.13%) |
| 最终存活 | 34/64 | 32/64 |
| 错误脚射门 | 6 | 2 |

准确要求方向误差≤10°、规定脚、前向速度相对误差≤30%；完整成功再要求20秒无失败。两个种子的完整成功分别为1→0、2→2。通过原始事件重算全部计数并校验两模型配对初态哈希。所有64回合保留在分母，评测不加载专家。本轮筛选失败，不替换默认模型。这个小样本结果不支持声称联合奖励带来收益，也不单独证明所有task-reward方案无效。

## 使用与视频

统一策略文件：`runs/planner_dual_task_reward_r3/unified_policy.pt`。使用 `from fiber_soccer.dual_task_deployment import load_soccer_policy` 加载，同一个实例支持 `policy(observation, skill="pass")` 和 `policy(observation, skill="shoot")`。调用方仍须维护真实动作历史和2406维观测，并在环境重置时调用 `policy.reset(done_mask)`。该文件是未通过性能筛选的实验权重。

- 训练前固定环境0–3：`dual_task_reward_videos/baseline_comparison.mp4`
- 训练后相同环境0–3：`dual_task_reward_videos/trained_comparison.mp4`
- 挑选的成功回合：`dual_task_reward_videos/trained_selected_success_env9.mp4`，seed819202/env9，是2/64成功中的一个。该环境在基线中也成功，不能将这个视频当作新增能力证据。
- 新传球专家参考：`dual_task_reward_videos/new_pass_expert_env0.mp4`，不属于planner成绩。

前后对比视频均为960×640、20秒、10fps；成功示例640×480、20秒；专家参考320×240、40秒。编码和轨迹哈希见视频manifest，已抽查实际画面。

正式训练后只修正了训练脚本开头关于专家辅助损失的文档描述；执行时的脚本快照及哈希仍保存在训练目录。汇总工具明确记录该事后源码变化，并用原始快照验证，未将当前文档改动误算为运行时改动。

下一步需要把新专家的传球蒸馏质量、射门分支自身退化、连续交接状态分布分开诊断。当前两分支分别训练后，原生射门也下降，不能只将失败归因于走路到射门的切换；也不应仅通过延长同一奖励设置的训练来宣称能解决。

视频来自实际Isaac rollout状态，MuJoCo仅进行前向计算和渲染；固定展示环境0–3，失败后画面停在首回合边界，不拼接重置后的片段。视频不单独构成成功率证据。
